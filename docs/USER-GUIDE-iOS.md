# UTUVO Type iOS 使用者手冊

> 適用於本分支的 iOS 原始碼版本，兩路由與單次交付的修改尚待發布。
> App Store 版本的介面可能不同；這份文件不宣稱新功能已經上架。

## 1. 安裝與啟用鍵盤

需要 iOS 18 以上。安裝主 App 後，到 iPhone **設定 → 一般 → 鍵盤 → 鍵盤 → 新增鍵盤**，加入 **UTUVO Type**，再開啟該鍵盤的 **允許完整取用**。

UTUVO Type 要求完整取用，讓鍵盤與主 App 配合處理語音、共享字典與歷史；這個權限本身不等於啟用雲端模式。沒有開啟時，App 會提示補足權限。

在其他 App 的輸入框按 **🌐** 切到 UTUVO Type。第一次開始語音工作階段時，可能需要開啟主 App，授權麥克風並啟動工作階段，再返回原本的 App。後續錄音由主 App 的背景語音工作階段處理，不需要一直停留在主 App 前景。

## 2. 選擇本機或雲端模式

到 **設定 → 語音處理路徑 → 處理方式**，或進入 **智慧整理** 選擇同一設定。主 App 與鍵盤共用這份選擇。

| 模式 | 語音辨識 | 文字整理 | 失敗時 |
| --- | --- | --- | --- |
| **本機・隱私優先** | Apple 裝置端辨識 | 可用的 Apple Intelligence；沒有 Apple Intelligence 的機型可使用已準備好的 Gemma | 整理不可用時保留辨識文字；沒有可用辨識器時直接提示 |
| **雲端・準確優先** | 選定的雲端辨識服務；可用時另保留 Apple 裝置端辨識結果作為備援 | 選定的文字整理服務 | 雲端失敗後回退本機完整整理；沒有本機辨識結果時，無法憑空恢復錄音內容 |

本機模式不會把音訊或待整理文字上傳到辨識／整理服務。Apple Intelligence 需要支援的機型與可用的系統模型；模型未就緒不會被當作整理成功。

**Qwen 只供主 App 前景聽寫使用。** 鍵盤在其他 App 使用時，不會嘗試執行需要前景 GPU 的 Qwen。

### 雲端設定與 key

1. 選擇「雲端・準確優先」，進入「智慧整理」。
2. 在「雲端文字整理服務」選服務，儲存自己的 API key；自訂服務還需要端點與模型名稱。
3. 在「雲端辨識服務」選擇錄音要送到的服務。辨識與文字整理可以選不同服務。
4. 某個辨識服務還沒有 key 時，可先在上方選該服務並儲存 key，再切回想用的文字整理服務。
5. 使用「測試」與「測試雲端辨識」檢查設定。這些測試會使用所選服務，可能消耗該服務額度。

每個階段只使用選定服務，不會因為儲存過其他 key 就默默換一家。

**升級舊設定時：** 已有的 Groq 等文字整理設定會保留，但「有文字整理 key」不代表允許上傳錄音。原本只使用文字整理的使用者，會看到「啟用雲端辨識」選項；明確啟用前，錄音仍留在本機。原本選擇只用裝置端的使用者維持本機模式。

Key 存在 Keychain，不會在設定頁回顯，也不寫入診斷紀錄。不要把 key 貼到 issue、PR 或截圖裡。

## 3. 在其他 App 裡語音打字

1. 點選輸入框並切到 UTUVO Type 鍵盤。
2. 點光球開始說話；辨識中的文字只出現在預覽區。
3. 停止錄音後等待「整理中…」。
4. 整理完成後，最終結果**一次貼入**輸入框，並依歷史保留設定記錄。

整理中再按光球，會提示等這段完成，不會先貼出未整理的版本又放棄整理。若等待期間換了輸入欄位，系統會保留安全邊界，不把這段插進另一個欄位，並記錄未交付原因。

關閉「智慧整理」時，不呼叫文字整理模型，仍會套用字典與基本文字格式規則。

選取文字後的改寫、幫我寫與問問題，其語音內容是指示，不會先被當作一般聽寫內容清理。改寫與翻譯遵循選定模式；本機模式不會因為有儲存 key 就把文字送到雲端。

## 4. 語言變體、中英間距與個人字典

聽寫語言與文字變體是不同設定。選擇 **台灣繁體** 時，輸出會套用正體字、台灣用語與中英間距：

| 辨識／模型文字 | 整理規則 |
| --- | --- |
| `使用ChatGPT和iOS26` | `使用 ChatGPT 和 iOS26` |
| `软件`、`軟件` | `軟體` |
| `数据库`、`數據庫` | `資料庫` |
| 字典指定 `臺灣大學` | 保留指定的「臺」，不改成「台」 |

香港、簡體與英文變體不套用台灣用語轉換。這次指令選定的變體會一路帶到輸出，不會因為下一句換了設定而改掉上一句。

在「個人字典」可加入：

- **詞彙**：專有名詞或慣用術語，供辨識與整理參考。
- **替換規則**：指定來源詞與輸出寫法，例如 `pik` → `Pik`。

字典指定的拼寫、大小寫與內部空格優先於一般格式規則。網址、Email 與反引號括住的程式碼也會受到保護。字典很多時，模型提示會依本句相關性選取，不代表一次把所有詞都送給模型。

「整理時參考前文」預設關閉。開啟後會使用有上限的游標前後文與欄位提示，協助理解語氣和指涉；本機模式交給本機模型，雲端模式交給所選服務。iOS 鍵盤不會假裝能取得宿主 App 名稱。

## 5. 主 App、歷史與診斷

主 App 分為 **聽寫／歷史／設定**。前景聽寫也採用辨識、整理、最後交付的流程。

歷史保留原始辨識與最終輸出；鍵盤的紀錄可在主 App 查看。是否保存及保存多久，依「歷史保留期限」設定。星標、複製與刪除仍在歷史頁操作。

「智慧整理 → 測試與診斷」區分交付次數與異常事件：

- 模型回覆通過驗證，只代表有候選文字，還不算交付。
- 網路失敗、逾時或驗證拒絕會留下各階段原因；雲端失敗不會用完本機回退的整份時間預算。
- 最後仍不能整理時，保留辨識結果，而不是丟掉這段話。
- 輸入欄位已變更時，記錄未貼入，不會宣稱成功。

診斷只記錄時間、服務、階段、字數與結果，不記錄逐字稿全文或 key。字典的既有 iCloud 同步是獨立功能，不等同於雲端辨識。

## 6. 驗收與已知限制

- 真實語音精度、Groq 延遲及背景錄音可靠度，需要在已簽章的 iPhone 上驗證。模擬器與 mock transport 測試不能取代實機測試；Debug 模擬器也可能使用合成逐字稿。
- 沒有可用的本機辨識器時，雲端模式仍可辨識，但斷網後沒有本機逐字稿可以回退。
- 整理驗證仍偏保守：允許指定詞彙修正與明確改口，不保證接受任意大幅改寫。
- 模擬器沒有螢幕鍵盤時，在 Device Hub 的 **Device → Keyboard** 關閉 **Simulate Hardware Keyboard**，再點輸入框；必要時使用 **Toggle Software Keyboard**。

開發與完整測試紀錄見 [iOS dictation routing](IOS-DICTATION-ROUTING.md)。
